# v1.1 队列自动重试（2026-09-15）

## 本次问题

本地记录中米白、酒红和灰色任务返回 HTTP 502，其中酒红和灰色各有 3 条手动尝试后的失败记录。旧版在任意任务失败后都会暂停整个队列，因此剩余任务一直排队。502 的具体服务商内部原因需要服务商日志确认，不能仅凭错误码认定是颜色或提示词问题。

## 改动

- 点击开始后，第一个请求立即启动，后续生成请求至少间隔 10 秒；仍遵守设置中的并发上限。不会在同一个请求尚未返回时重复发起该任务。
- HTTP 408、429、5xx、连接中断或请求超时：同一任务自动重试，首次加重试共最多 **3 次**；每次失败后至少等待 10 秒，并受并发上限和请求间隔限制。
- 前两次临时失败显示 **Retrying 1/3、Retrying 2/3**；第三次仍失败才显示 **Failed 3/3**，启用 Regenerate，并继续其他排队任务。成功后立即停止重试。
- 密钥、参数、证书或无法识别的异常直接失败并暂停，修正配置后再继续，避免重复提交相同的无效请求。
- 每条任务保存尝试次数、每次开始/结束时间及错误。暂停/恢复不会重置次数。重启软件后不会自动运行；点击开始才继续等待中的重试，次数保留。
- Pause 会暂停新请求和重试；Cancel queued 会取消排队和待重试任务。已发出的请求仍会完成，取消后的失败请求不会再次自动重试。
- “Retry failed / 重试失败任务”：为失败或中断任务创建新版本，旧记录和图片保留，避免重复加入已有重试。新版本获得新的 3 次尝试额度。重试可能产生新的 API 费用，特别是上次请求已经处理但响应未收到的情况。
- 失败数量包含历史失败版本，不会因新版本成功而删除历史错误。

## 使用新版继续现有任务

1. 先退出旧版（如有正在运行的请求，等待完成），避免两个程序同时写同一份任务记录。
2. 打开 `FabricLabelStudio-v1.1` 文件夹里的 `FabricLabelStudio.exe`，保留旁边的 `_internal` 文件夹。窗口标题和左下角会显示 **v1.1**。
3. 默认自动读取同一 Windows 用户的原有设置、任务和图片，无需重新导入。
4. 已有排队任务直接点击“开始”；如果只剩历史 Failed 记录，先点击“重试失败任务”，再点击“开始”。
5. 要单独补生成某种颜色，选择其失败任务点击“Regenerate / 重生成”。新版本会按最多 3 次、至少间隔 10 秒执行。

测试仅使用本地样本和模拟错误；未验证服务商当前可用性，也未提交用户的付费生成请求。10 秒是等待间隔，图片生成请求自身可能需要数分钟。
