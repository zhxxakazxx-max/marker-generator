# v1.2 批量重新生成（2026-09-15）

在审核页选中多个任务，即可一次加入重新生成队列，无需逐条点击。每个新版本都有独立记录，旧图片和旧状态保留。

## 操作步骤

1. 打开 **审核 / Review** 页，在任务列表中按住 **Ctrl** 点击多个不连续的行，或按住 **Shift** 点击选择连续范围。
2. 点击 **Select all / 全选** 可选中整个列表；点击 **Clear / 清空** 可取消全部选择。全选可能包含正在运行的任务，提交时会按下方规则跳过。
3. 如需统一调整，在原有反馈输入框填写共同的修改要求，例如“标签文字更清晰，保留当前面料颜色”。输入框非空时，这份要求会用于每个新版本；输入框留空时，各新版本分别沿用原任务已有的修改意见。
4. 点击 **Regenerate selected / 批量重生成**。提示栏显示本次新增排队版本数量，以及跳过的选中行数量。
5. 队列暂停时，点击 **Start / 开始** 执行；队列已在运行时，新版本会加入现有队列继续处理。

列表自动刷新和执行批量操作后，已选中的原任务仍保持选中。可继续调整选择，或点击 **Clear** 清除。

## 哪些任务会加入队列

| 所选任务的状态或情况 | 批量操作结果 |
| --- | --- |
| Failed（失败）、Review（待审核）、Approved（已批准）、Cancelled（已取消）、Interrupted（已中断） | 每条任务新增一个排队子版本 |
| Queued（排队）、Running（运行中）、Retrying（等待自动重试） | 跳过该行 |
| 原任务已有一个直接子版本处于 Queued、Running 或 Retrying | 跳过原任务，避免重复加入尚未完成的新版本 |

跳过的行不会创建新任务。若没有符合条件的选中任务，批量按钮不可用，计数显示 0 个可重生成；等待已有任务完成，或重新选择符合条件的任务后再操作。

## 版本、备注与重试

- 批量操作保留原任务的图片、状态、尝试次数和历史记录，只新增排队子版本。
- 新版本使用原任务的成分、面料颜色和参考设置。反馈框有内容时使用共同的修改意见；反馈框为空时分别保留原备注。
- 每个新版本已用尝试次数从 **0** 开始，首次请求加自动重试最多 **3 次**。
- 沿用 v1.1 的调度规则：请求启动至少间隔 **10 秒**，同时遵守并发上限。临时失败后至少等待 10 秒才重试。10 秒是请求间隔，单张图片生成本身可能需要更久。
- 暂停不会启动新请求；正在进行的请求会继续完成。重新点击开始后继续处理队列。
- 历史失败版本仍计入失败数量。旧版本已获批准时，其批准状态也保留；审核、批准和导出前请确认所需版本。

批量重新生成会提交新的模型请求，费用由所选服务商收取。新增批量操作不改变 API 配置和模型要求。

## 使用 v1.2 继续已有任务

1. 等待旧版正在进行的请求完成，再退出旧版。
2. 本地程序位于 `D:\Marker\FabricLabelStudio-v1.2\FabricLabelStudio.exe`。使用该目录内的程序，并保留旁边的 `_internal` 文件夹。窗口标题和左侧栏的版本标识应显示 **v1.2**。
3. 同一 Windows 用户下，程序读取 `%LOCALAPPDATA%\FabricLabelStudio` 中已有的设置、任务和图片，无需重新导入。
4. 软件重新打开后不会自动开始请求。选择需要重做的任务，点击 **Regenerate selected**，再点击 **Start / 开始**。

本说明介绍操作与队列规则，不代表服务商当前可用性或真实 API 生成结果已经验证。自动重试的原始说明见 [v1.1 队列自动重试](QUEUE_FIX.zh-CN.md)。
